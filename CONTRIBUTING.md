# Contributing, reproducing and correcting records

We welcome evidence-backed corrections and reproducibility improvements. For a catalog correction, open an Issue with the **exact original public GitHub permalink**, the specific false or stale claim, and the supported replacement.

For new contributions include: original upstream project, source link, exact source revision, test file hash (when applicable), negative and positive controls, actual command/outcome, true code author and unambiguous claim level. Do not add multiple copies of the same comment.

For upstream code submissions, follow the original project's contributor policy. An AETHER public candidate test is not an upstream accepted PR. Do not publish new external posts or make modifications on our behalf without explicit authorization.

Do not include confidential account data, unreleased vulnerabilities, private repository links, host identities or unredacted logs. Read [SECURITY.md](SECURITY.md).
